# 위험 패턴 유형표 (Risk Pattern Matrix)

> 시드 데이터 수집의 커버리지 관리 기준표.
> 스펙 §14 "위험 패턴 유형표를 먼저 만들고 유형별 최소 수량을 채우는 방식으로 수집"의 실행 문서.
> 작성일: 2026-07-12 / 상태: v0.1 (수집 진행 중 갱신)

## 목적

- 시드 400+ 문장을 **무작정 모으지 않고**, 7개 카테고리 × 3개 위험도 = 21칸의 커버리지를 채우는 방식으로 수집한다.
- 특정 카테고리/클래스 편중(클래스 불균형)을 수집 단계에서부터 방지한다.
- 각 칸의 "대표 패턴"은 이후 `labeling-guideline.md`의 판단 기준과 Baseline 1(키워드 규칙)의 원천이 된다.

## 수량 목표

| 구분 | 목표 |
|---|---|
| 전체 시드 | 400~600문장 |
| 칸별 최소 수량 | **10문장** (강제) |
| 칸별 상한 | 없음 — 자연 분포 허용 (정상 조항이 실제로 더 흔함) |
| 위험도별 비율 가이드 | safe 40~50% / caution 25~35% / danger 25~35% (심한 쏠림만 방지) |

## 유형표 (7 카테고리 × 3 위험도)

카테고리 코드는 시드 CSV의 `category` 컬럼 값과 일치시킨다.

### 1. 보증금 반환 (`deposit_return`)

| 위험도 | 대표 패턴 | 예시 문형 |
|---|---|---|
| safe | 반환 시기·방법 명확, 법정 수준 | "임대인은 계약 종료와 동시에 보증금 전액을 임차인에게 반환한다" |
| caution | 반환 조건이 붙지만 상한/기한 존재 | "보증금은 임차인 퇴거 확인 후 3일 이내 반환한다" (즉시 반환이 아님) |
| danger | 반환을 새 임차인·임대인 사정에 종속 | "새로운 임차인이 입주하기 전까지 보증금 반환을 유예한다", "보증금에서 공제할 항목은 임대인이 정한다" |

### 2. 수리·하자 (`repair_defect`)

| 위험도 | 대표 패턴 | 예시 문형 |
|---|---|---|
| safe | 주요 설비(보일러·배관·누수 등) 수선은 임대인 부담 명시 | "보일러, 배관 등 주요 설비의 고장은 임대인이 수리한다" |
| caution | 책임 구분이 있으나 범위 모호 | "소모품 수리는 임차인 부담으로 한다" (소모품 정의 없음) |
| danger | 수리 책임 전부 임차인 전가, 임대인 면책 | "본 건물의 모든 수리는 임차인의 부담으로 한다", "하자에 대해 임대인은 책임지지 않는다" |

### 3. 원상복구 (`restoration`)

| 위험도 | 대표 패턴 | 예시 문형 |
|---|---|---|
| safe | 통상 마모(자연 손모) 제외 명시 | "임차인은 고의·과실로 인한 훼손에 한해 원상복구한다" |
| caution | 원상복구 조항은 있으나 범위 미명시 | "퇴거 시 임차인은 원상복구한다" |
| danger | 통상 마모 포함 전부 복구, 특정 공사 강제 | "통상적인 마모를 포함하여 입주 시 상태로 복구한다", "퇴거 시 도배·장판을 임차인 부담으로 전면 교체한다" |

### 4. 계약 해지·갱신 (`termination_renewal`)

| 위험도 | 대표 패턴 | 예시 문형 |
|---|---|---|
| safe | 법정 갱신요구권·묵시적 갱신 존중 | "계약 갱신은 주택임대차보호법에 따른다" |
| caution | 통보 기한·위약 조건이 법정 기준보다 임차인에게 다소 불리 | "중도 해지 시 임차인은 중개보수를 부담한다" |
| danger | 갱신요구권 포기, 임대인 임의 해지, 과도한 위약금 | "임차인은 계약갱신요구권을 행사하지 않기로 한다", "임대인은 필요 시 계약을 해지할 수 있다", "중도 해지 시 보증금의 10%를 위약금으로 한다" |

### 5. 근저당·권리관계 (`lien_rights`)

| 위험도 | 대표 패턴 | 예시 문형 |
|---|---|---|
| safe | 잔금일 익일까지 추가 담보 설정 금지, 대항력 확보 협조 | "임대인은 잔금 지급일 다음 날까지 근저당권 등 새로운 권리를 설정하지 않는다" |
| caution | 기존 근저당 존재를 언급하나 상환·말소 계획 불명확 | "본 건물에는 채권최고액 1억원의 근저당권이 설정되어 있음을 임차인이 확인한다" |
| danger | 권리 하자에 대한 이의 포기, 추가 설정 동의, 전입·확정일자 제한 | "임차인은 현재 등기사항을 확인하였으며 향후 이의를 제기하지 않는다", "임대인의 추가 대출 및 근저당 설정에 임차인은 동의한다", "임차인은 전입신고를 하지 않기로 한다" |

### 6. 관리비·공과금 (`fees_utilities`)

| 위험도 | 대표 패턴 | 예시 문형 |
|---|---|---|
| safe | 항목·금액·부담 주체 명확 | "관리비는 월 7만원으로 하며 수도·인터넷 요금을 포함한다" |
| caution | 관리비 존재하나 금액·항목·인상 조건 모호 | "관리비는 별도로 한다" |
| danger | 임대인 임의 인상, 포괄 청구, 부당 전가 | "관리비는 임대인이 필요에 따라 조정할 수 있다", "건물 수선충당금은 임차인이 부담한다" |

### 7. 기타 (`etc`)

| 위험도 | 대표 패턴 | 예시 문형 |
|---|---|---|
| safe | 통상적 생활 규칙, 법정 내용 재확인 | "임차인은 애완동물을 사육하지 않는다", "기타 사항은 주택임대차보호법 및 관례에 따른다" |
| caution | 임차인 권리를 다소 제한하거나 의미가 모호한 조항 | "임차인은 임대인의 사전 동의 없이 시설물을 변경할 수 없다" |
| danger | 제소전화해 강제, 임차권등기 금지 등 법적 대응 봉쇄 | "임대인 요구 시 임차인은 제소전화해 조서 작성에 협조하며 비용을 부담한다", "임차인은 임차권등기명령을 신청하지 않는다" |

## 커버리지 트래커

수집이 진행되면 아래 표의 수치를 갱신한다. (`ml/scripts/coverage.py`로 자동 집계 예정 — 2주차)

최종 갱신: 2026-07-12 (1차 배치 — 표준계약서 + 가이드·칼럼)

| 카테고리 | safe | caution | danger | 소계 |
|---|---|---|---|---|
| deposit_return | 5 | 0 | 1 | 6 |
| repair_defect | 7 | 0 | 3 | 10 |
| restoration | 4 | 0 | 2 | 6 |
| termination_renewal | 11 | 0 | 4 | 15 |
| lien_rights | 8 | 0 | 0 | 8 |
| fees_utilities | 2 | 0 | 0 | 2 |
| etc | 5 | 0 | 0 | 5 |
| **합계** | **42** | **0** | **10** | **52 / 400** |

**부족 칸 (다음 배치 우선순위)**: caution 전 카테고리(0건 — 가이드류는 "좋은 특약/나쁜 특약"만 다루고
모호·미명시 사례를 다루지 않음. 커뮤니티 실사례 + 직접 작성으로 채울 것),
`fees_utilities` 전반, `lien_rights`·`etc`·`deposit_return`의 danger.

## 수집 출처 우선순위 (스펙 §5.2 Step 1)

1. **국토교통부 주택임대차표준계약서** — safe 클래스의 뼈대. 저작권 문제 없음. `standard_clauses` 마스터의 원천으로 재사용.
2. **전세사기 예방 가이드·법률 칼럼의 특약 예시** — danger/caution의 핵심 소스.
3. **부동산 커뮤니티 실제 특약 문구** — 실전 문체 다양성. 개인정보(이름·주소·금액 등 식별 가능 정보) 제거 후 수록.
4. **직접 작성 변형 문장** — 유형표에서 최소 수량 미달인 칸을 채우는 용도. 수집 마지막 단계에 수행.

## 주의사항

- `uncertain`은 **모델의 출력 상태이지 라벨이 아니다.** 시드 라벨은 safe/caution/danger 3종만 사용한다.
- 한 문장에 여러 카테고리 성격이 섞이면 **가장 위험한 축**의 카테고리를 부여하고, 경계 사례로 `labeling-guideline.md`에 기록한다.
- 수집 시점의 라벨은 잠정 라벨이며, 2주차 본 라벨링(가이드라인 기반 + 자기 일치도 검증)에서 확정한다.
