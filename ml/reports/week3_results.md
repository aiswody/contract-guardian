# 3주차 모델 결과 리포트

> 모든 수치는 `ml/scripts/eval_utils.py` 기준 (Macro-F1 + danger Recall).
> **개발 중 평가는 val(34문장)만 사용.** test(34문장)는 3주차 말 최종 비교에서 1회만 개봉.
> val이 작아(클래스당 9~14건) 수치의 신뢰구간이 넓다는 점을 감안할 것 (2주차 기록 참조).

## 위험도 3-class — val 결과

| 모델 | Macro-F1 | danger Recall | 비고 |
|---|---|---|---|
| Baseline 1 — 키워드 규칙 | 0.537 | 0.455 | danger precision 1.000 (규칙에 걸리면 확실하나 절반을 놓침) |
| Baseline 2 — TF-IDF + LR | 0.530 | 0.545 | train 0.992 → val 0.530, 심한 과적합 |

| **KLUE-RoBERTa-base 2차 (채택)** | **0.749** | **0.727** | `train_local.py` — 에폭 8 중 5번째 체크포인트 선택 (결합 점수 기준) |

### 2차 학습 결과 분석 (val)

- baseline 대비: Macro-F1 +0.21, danger Recall +0.18~0.27. **채택.**
- danger FN 3건이 남는데, 셋 다 confidence 0.99의 확신에 찬 오답 —
  threshold로 구제 불가 (아래 threshold 분석 참조).
- **FN 3건의 근본 원인**: 화재보험료 전가·신탁 무동의·임대인 인정 해지 —
  층화 분할에서 해당 희소 패턴의 시드가 전부 val/test로 가서 **train에 유사 문장이
  0건**인 패턴들. 229 시드 규모에서 1~2건뿐인 패턴은 분할 운에 따라 학습 불가능해짐.
- 시도한 보완 — **규칙 danger 백스톱 하이브리드** (`hybrid_eval.py`): 규칙 baseline의
  danger precision 1.0을 이용해 "규칙이 danger면 상향" 정책을 검증 → val 개입 0건
  (규칙이 잡는 danger는 모델도 이미 잡음). 규칙 사전을 val 오답에 맞춰 보강하는 것은
  검증셋 누수이므로 하지 않음. 구조만 유지하고 규칙 확장은 새 시드 수집 시 재평가.
- 남은 개선 경로 (v1.5): 희소 패턴 시드 보강 후 재분할·재학습, 실사용 피드백 데이터 편입.

### threshold (`확인 필요`) 분석 — val

| threshold | uncertain | 커버리지 | 유효 danger 놓침 |
|---|---|---|---|
| 0.7 | 2건 | 94% | 3/11 (27%) |
| 0.9 | 5건 | 85% | 3/11 (27%) |

- v2 모델은 확신이 강해(conf 평균 0.94) threshold를 올려도 FN이 줄지 않는다.
  **threshold는 0.7로 결정** — 커버리지 손실 대비 이득이 없는 상향은 무의미.
  uncertain 처리의 실효성은 경계 문장(협의·조정류)에 한정됨을 문서화.

### 1차 학습 실패 진단 (기록)

- 증상: danger Recall 0.273으로 baseline보다 낮음. train 데이터에서조차 Macro-F1 0.796,
  confidence 평균 0.69 — 자기 학습 데이터도 못 맞히는 과소학습 상태.
- 대조군: 동일 스크립트의 카테고리 모델은 train 1.000 / val 0.840으로 정상 학습됨.
- 원인: `load_best_model_at_end`가 **34문장 val의 macro-F1 단독**으로 best를 선택 —
  위험도 과제는 val 수치 요동이 커서 덜 배운 초기 에폭 체크포인트가 우연히 선택됨.
- 조치 (`train_local.py`): ① 에폭 5→8, ② best 선택 기준을 (Macro-F1 + danger Recall)/2
  결합 점수로 변경 — FN 최소화 원칙의 학습 단계 적용, ③ danger 가중 손실(1.5배).
- 교훈: 작은 val로 체크포인트를 고를 때는 선택 지표가 서비스의 비용 구조(danger FN)를
  반영해야 한다.

### 해석

- 규칙 기반(B1)은 danger precision 1.0 — 유형표의 대표 패턴이 정확하다는 방증.
  그러나 표현이 조금만 변형돼도 놓친다 (Recall 0.455). "패턴 사전으로는 재현율을
  못 채운다"가 파인튜닝의 존재 이유.
- TF-IDF(B2)는 train을 통째로 외웠지만 val(증강 없는 시드 원본)에서 무너짐 —
  표면 n-gram이 아니라 의미 이해가 필요하다는 근거.
- val 34문장 기준 오차가 크므로, baseline 간 우열(0.537 vs 0.530)은 유의미한
  차이로 해석하지 않는다.

## test set 개봉 기록 — 2026-07-12, 1회 실행 (`final_test_eval.py`)

| test (34문장, danger 11) | Macro-F1 | danger Recall | danger FN |
|---|---|---|---|
| Baseline 1 (규칙) | 0.617 | 0.455 | 6건 |
| Baseline 2 (TF-IDF+LR) | 0.525 | 0.545 | 5건 |
| KLUE-RoBERTa v2 위험도 | 0.462 | **0.636** | **4건** |
| KLUE-RoBERTa 카테고리 | **0.967** | — | — |

- threshold 0.7 적용 시 v2: uncertain 2건, 유효 danger 놓침 3/11.

### 정직한 해석

1. **1순위 지표(danger Recall)는 v2가 최고** — FN 최소화 관점에서 세 모델 중 위험 조항을
   가장 적게 놓친다. 카테고리 모델은 0.967로 확실한 성공.
2. **그러나 위험도 Macro-F1은 baseline 이하** — caution 클래스가 test에서 붕괴(9건 중 1건).
   val 0.749 → test 0.462의 간극은 과대적합이 아니라 **평가 프로토콜의 한계**:
   34문장 val로 체크포인트를 고르고 34문장 test로 검증하면, 두 셋의 우연한 구성 차이가
   모델 실력 차이보다 클 수 있다 (클래스당 9~14건 → 1건에 ±7~11%p).
3. **교훈 (다음 사이클 반영)**: 이 데이터 규모에서는 고정 분할보다 k-fold 교차검증이
   맞는 프로토콜이었다. v1.5 재학습 시 (1) 희소 패턴 시드 보강, (2) 5-fold CV로
   모델 선택, (3) 평가셋 확대를 함께 적용한다.
4. 봉인 원칙에 따라 본 수치는 현 모델(v2 + threshold 0.7) 기준으로 확정하며,
   이후 모델 변경 시 test 재사용 없이 새 평가 데이터로 검증한다.
